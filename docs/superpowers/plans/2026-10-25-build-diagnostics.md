# Default-branch build diagnostics implementation plan

> **For agentic workers:** Use the systematic-debugging and verification-before-completion skills. Independent app diagnostics and test-host setup are delegated; the parent owns integration and CI.

**Goal:** Verify post-merge develop CI, remove repository-owned build warnings and deprecations, and submit the fixes as a new PR.

**Architecture:** Keep existing behavior for mechanical diagnostic cleanup. Correct the reproduced message observation and paging bugs. Run native tests in a minimal scene-capable host instead of deprecated scene-less windows; keep test code shared with the Swift package.

**Tech stack:** Swift 5 language mode, SwiftUI/UIKit, Xcode, Swift Package Manager, SwiftLint, fastlane/GitHub Actions.

## Constraints and evidence

- Retain the iOS 26 deployment floor, all native composer tests, and production signing requirements.
- Do not suppress compiler/deprecation warnings or bypass signing/test failures.
- Prior CI logs and clean local build logs reproduce missing imports, unused bindings, ownership/conformance diagnostics, UIKit deprecations, and build-script warnings.
- Red tests reproduce stale scroll requests, non-reflexive loading/failure equality, and ignored reaction/role/resolution updates.
- The standalone Swift package test process has no window scenes; native window hosting needs an app target.

## Review focus

Test hosts must not launch production startup or network services. Paging must preserve a reader's location when history is prepended, while newly arrived messages remain reachable. Message observation must compare stable values rather than randomized hashes. Signing credentials remain external configuration; report authentication failures separately from compilation/test defects.

## Verification record

- Baseline default-branch test jobs both passed; their build jobs failed independently on missing self-hosted Ruby 4.0.9 and GitLab certificate authentication. The user explicitly left signing credentials out of scope.
- Red tests reproduced stale paging, non-reflexive loading/failure equality, and ignored emoji/role/resolution updates before fixes.
- The first focused hosted run passed, but full verification exposed a name collision with SwiftPM's autogenerated `ArtemisKitTests` scheme. The unique `ArtemisKitHostedTests` scheme resolves it; its xctestrun declares an app-hosted bundle and the expected minimal host.
- Final hosted build and all **232 tests pass on each of iPhone 17 Pro and iPad Pro 11-inch (M4), iOS/iPadOS 26.2**, with zero warning diagnostics.
- Production **Debug Simulator and unsigned Release iOS-device builds succeed with zero warning diagnostics**. Full-repository strict SwiftLint, shellcheck, actionlint, Ruby/shell syntax and diff checks pass. Eight CLI-helper cases pass under Ruby 2.6 and 4.0.9.
- Independent review fixes preserve bottom alignment for short conversations, resolve pinned lint dependencies before use, and scope log checks to fresh run logs. No signing checks are bypassed.
- Shared-package sources are pinned to the comments/documentation-only [core-modules PR #217](https://github.com/ls1intum/artemis-ios-core-modules/pull/217).
